# Embedded Hardware Safety Review — AI 代码烧板子审查器

> **一个为嵌入式 AI 代码生成的 60 项硬件安全审查技能。**
>
> AI 写的代码语法正确，但物理上危险。LLM 不懂电流、电压、热量——它把 GPIO、PWM 定时器、PID 回路当作抽象文本来处理，毫无物理后果意识。

## 为什么需要这个 Skill？

| AI 生成的代码 | 物理后果 |
|-------------|---------|
| `PWM_Frequency = 50Hz` | 电机啸叫+MOS 管烧毁 |
| `GPIO_Mode_Out_PP` on encoder pin | IO 口烧毁/MCU 锁死 |
| 无 PID 积分限幅 | 过冲→甩尾→撞墙 |
| 无看门狗 | I2C 卡死→小车全速冲出去 |
| `asin()` 输入无值域检查 | NaN→100% 占空比→撞墙 |
| 无电池电压检测 | 低压→MCU 复位→GPIO 乱跳→倒车撞裁判 |
| `HAL_Delay(100)` 被 AI 删除 | 外设未初始化完→全比赛随机数据 |

**这个 Skill 在 AI 生成代码之后、上电之前，强制执行 60 项物理安全检查。**

## 安装

```bash

cp -r embedded-hardware-safety-review ~/.claude/skills/
```

### 方法 2：通过 GitHub 安装


## 使用方式

### 触发条件

Skill 在以下情况下自动激活：

- 提交嵌入式代码要求安全审查
- 提到关键词：`嵌入式安全审查`、`电机驱动审查`、`STM32安全`、`PWM安全`、`MPU6050安全`、`姿态解算审查`、`舵机安全`、`平衡车安全`、`麦轮安全`、`竞赛安全`、`封车安全`
- AI 生成电机控制/传感器融合/状态机代码时主动触发自我审查
- 提到硬件安全风险：烧毁、冒烟、失控、炸驱动、卡死、飞车、变砖、HardFault

### 手动触发

```
用 embedded-hardware-safety-review 审查这段代码
```

### 输出格式

审查完成后输出结构化报告，包含：
- **总体严重级别**（CRITICAL / HIGH / MEDIUM / LOW）
- **60 项逐项检查结果表格**（✅/❌/⚠️/⏭️）
- **上电前必须修复的致命问题清单**
- **需要手动实测验证的项目清单**
- **完整的修复代码片段**

## 触发条件说明

每项检查都标注了触发条件：

- **通用项** — 适用于所有嵌入式项目
- **[SERVO]** — 仅当系统包含舵机
- **[BALANCE]** — 仅当系统为两轮平衡车
- **[MECANUM]** — 仅当系统使用麦轮/全向轮
- **[VISION/LINE]** — 仅当系统包含摄像头/灰度循迹
- **[WIRELESS]** — 仅当系统使用蓝牙/WiFi 遥控
- **[CAMERA+IMU]** — 仅当系统融合摄像头与 IMU 数据
- **[COMPETITION]** — 仅当系统用于竞赛场景
- **[ENCODER]** — 仅当系统包含编码器

审查时自动跳过不适用的条件项。

## AI Prompt 前缀模板

每次向 AI 生成嵌入式代码时，在 Prompt 开头粘贴以下内容即可从源头拦截大部分问题：

```
请严格遵循以下嵌入式安全约束（违反任何一条都可能导致硬件烧毁、人员受伤或板子变砖）：

【物理层】
1. PWM固定15kHz，占空比限幅[-85%,+85%]，速度闭环用rpm/cm·s⁻¹非PWM%
2. 急停50ms斜坡减速，禁止瞬间拉0%；优先滑行停止
3. 传感器输入引脚IN_FLOATING/IPU/AF_OD，绝不用Out_PP
4. EN默认低电平；上电：PWM=0%→延时100ms→EN拉高
5. 电池电压ADC实时监测+前馈补偿：PWM×(额定/当前)，上限1.5×
6. 动态负载检测：急加速电压跌>0.8V→限制加速度；累计mAh做独立电量
7. 每个TIM_SetCompare前5行内必须有内联if(pwm>MAX→pwm=MAX)
8. 外接急停按键(常闭)：硬件直连EN到GND+软件EXTI最高优先级

【算法层】
9. PID积分分离+I项限幅+输出限幅；参数切换bumpless transfer
10. asin/sqrt/除前值域检查；PID输出isnan()守护
11. 姿态更新硬件定时器中断(≥200Hz)，禁止delay()
12. 编码器定时器模式TI12+5-10窗口滑动平均
13. 转向-速度耦合；阿克曼后轮禁止差速
14. 速度目标值一阶低通滤波，禁止0→100跳变
15. 陀螺零偏动态补偿；加速度计运动时动态降权
16. 视觉/灰度阈值动态更新(OTSU/min-max每100ms)

【逻辑层】
17. 使能IWDG(4秒)，仅主循环末尾喂狗
18. 中断优先级：急停>姿态/电机(0-1)>I2C/ADC(2-5)>串口(14-15)
19. 电池低于阈值关EN，不自动恢复
20. 状态机每个状态带超时→STATE_ERROR
21. 按键定时器10ms轮询+3次一致

【总线层】
22. I2C/SPI≤10ms超时；超时后RCC时钟关断+外设复位+重初始化
23. 串口DMA环形缓冲区+IDLE中断
24. 无线心跳500ms；≥10次丢包=断开；关键任务无视遥控

【赛场生存】
25. RAM错误日志(≥16条环形缓冲)；长按2秒LED闪烁回放
26. Flash双配置(保守+激进)；硬件引脚安全模式
27. PID平时只存RAM；仅长按5秒+电机停转才写Flash
28. 左右轮机械零偏必须实测补偿

【永不触碰】
29. PA13(SWDIO)/PA14(SWCLK)调试阶段绝不复用为GPIO
30. 外设初始化延时不可删除；初始后WHO_AM_I验证
```

## 贡献

这个 Skill 是实战经验的结晶——每一项都来自真实的硬件烧毁、比赛失利和深夜调试。如果你有自己的"血泪教训"，欢迎提交 PR 添加新的检查项。

### 添加新项目的格式

每个检查项需要包含：
1. **场景描述**：AI 为什么会犯这个错误
2. **赛场实锤**：实际导致过什么后果
3. **错误代码示例**：❌ AI 常写的错误代码
4. **正确代码示例**：✅ 修复后的代码
5. **验证规则**：如何检查代码是否符合要求
6. **修复动作**：FAIL 时的具体修复步骤
